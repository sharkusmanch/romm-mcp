# RomM 5.4 Compatibility Implementation Plan

> **For agentic workers:** Execute with test-driven development and independent adversarial review.

**Goal:** Preserve full API coverage and capability controls on RomM 5.4, then deploy and verify both services.

**Architecture:** Retain the compact tools and schema-driven executor. Add explicit definitions for upstream WebDAV routes omitted from OpenAPI; extend existing realtime sessions. Keep bounded outputs, fixed upstream origin, credential isolation, and independent write verification.

**Tech Stack:** Python, MCP 2.3, HTTPX, Socket.IO, pytest, GitHub Actions, Flux.

**Spec:** Approved compatibility assessment in this session, based on upstream RomM tag 5.4.0.

## Constraints and review focus

- Preserve current cluster capability flags; new privileged operations must honor them.
- No redirects, arbitrary destinations, caller filesystem paths, or credential leakage.
- Pending conversion HTTP 202 must not produce an empty download artifact.
- WebDAV paths, Destination headers, raw bodies, XML and nonstandard methods must be bounded and constrained.
- Netplay must authenticate with session cookies and reject legacy password payloads instead of silently opening unprotected rooms.
- Preserve existing 5.3.1 compact behavior; test 5.4 additions against official source.
- Release with existing image/provenance/SBOM workflows; use hosted Renovate app.
